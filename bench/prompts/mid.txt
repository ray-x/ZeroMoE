Summarize the following notes in three bullet points. # Building ZeroMoE against a patched ggml Status 2026-10-23: the patch series is **ported to upstream llama.cpp 8baabd53b (ggml 0.27.0)** and applies with plain git apply (no fuzz). The ggml that the earlier Ling and MiMo gates ran against was a prebuilt directory that was deleted by accident, and how it was patched had not been written down; this file and scripts/build_ggml.sh are now the record. ## Rules 1. **A ZeroMoE binary must not depend on a directory it does not own.** The binary records the ggml directory as its RUNPATH. If that directory disappears, the loader silently falls back to the system /usr/lib/libggml* (sm_86 only, no PTX), and any kernel on the sm_120 GPU (RTX 5060 Ti) fails with CUDA error: no kernel image is available ... ggml_cuda_kernel_can_use_pdl. A running process keeps working (its libraries are already mapped), which hides the problem until the next start. 2. **Where builds live:** - a build of master (master's ggml patch series) lives inside the main checkout (build_master, build_ggmlcuda); - a build that needs branch-only ggml patches lives in that branch's worktree, and may be deleted when the worktree is merged back and removed. 3. scripts/build_with_ggml.sh <build-dir> refuses a GGML_PREBUILT that sits inside *another* worktree. 4. The way a ggml tree is patched must be a script or a document in this repo, never a one-off command. ## The series patches/ggml then patches/ggml-host-node, in filename order, rooted at the ggml directory (a/src/...), applied by scripts/build_ggml.sh (and by cmake/ZeroMoEGgmlPatches.cmake when CMake builds ggml itself) with git apply --directory=ggml. A patch that does not apply stops the build.
