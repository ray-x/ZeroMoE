Summarize the following notes in five bullet points. # Building ZeroMoE against a patched ggml Status 2026-10-23: the patch series is **ported to upstream llama.cpp 8baabd53b (ggml 0.27.0)** and applies with plain git apply (no fuzz). The ggml that the earlier Ling and MiMo gates ran against was a prebuilt directory that was deleted by accident, and how it was patched had not been written down; this file and scripts/build_ggml.sh are now the record. ## Rules 1. **A ZeroMoE binary must not depend on a directory it does not own.** The binary records the ggml directory as its RUNPATH. If that directory disappears, the loader silently falls back to the system /usr/lib/libggml* (sm_86 only, no PTX), and any kernel on the sm_120 GPU (RTX 5060 Ti) fails with CUDA error: no kernel image is available ... ggml_cuda_kernel_can_use_pdl. A running process keeps working (its libraries are already mapped), which hides the problem until the next start. 2. **Where builds live:** - a build of master (master's ggml patch series) lives inside the main checkout (build_master, build_ggmlcuda); - a build that needs branch-only ggml patches lives in that branch's worktree, and may be deleted when the worktree is merged back and removed. 3. scripts/build_with_ggml.sh <build-dir> refuses a GGML_PREBUILT that sits inside *another* worktree. 4. The way a ggml tree is patched must be a script or a document in this repo, never a one-off command. ## The series patches/ggml then patches/ggml-host-node, in filename order, rooted at the ggml directory (a/src/...), applied by scripts/build_ggml.sh (and by cmake/ZeroMoEGgmlPatches.cmake when CMake builds ggml itself) with git apply --directory=ggml. A patch that does not apply stops the build. Ported to 0.27 (same intent, rebased hunks): 0001 (Q2_0 VNNI; its arch-fallback.h hunk is gone because upstream no longer defines the generic alias on x86), 0002 (negative-id skip; the new mul_mat_vec_q_moe kernel needed the check added by hand), 0003 (CUDA graph capture on first call plus the stream/graph bridges), 0004 (padding clear bounded by the buffer size; upstream now uses cudaMemsetAsync), 0010 (f32 quant hook in ggml_cuda_mul_mat), 0012 (GGML_API on ggml_graph_view). 0005, 0006, 0009, 0013 and the host-node series applied as written. patches/ggml-host-node/0003 (early-ready private CPU, the ggml_backend_sched_early_cpu_supported symbol) was copied from the Ling worktree. Moved to patches/obsolete (they target the older upstream): 0007 and 0008 (they patch the scheduler's built-in MUL_MAT_ID expert copy, which upstream replaced with ggml_backend_sched_set_copy_callback; ZeroMoE's ExpertCopy uses that callback; 0008's ZEROMOE_SCHED_EVENTS has no equivalent yet, MiMo's op-offloaded prefill sets it, effect unmeasured), 0011 (bridge-only variant of 0003 for newer context; 0003 now carries the bridge) and the 0007-sched-early-cpu-hook text patch (superseded by host-node/0003).
